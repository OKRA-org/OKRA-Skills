# 書店訪問メモから営業報告を作る

書店を回った営業担当者は、訪問後にメモを読み返し、要望や宿題を CRM や表に入力し、上司向けの報告を書いている。訪問件数が多いと入力が後回しになり、「言われたこと」と「決まったこと」が混ざりやすい。このスキルは「メモを共通の項目に整理する・合意と検討中を分ける」を担い、「受注かどうか・数量と期日の正確さ・何を記録に残すか」は営業担当者が判断する。

## 入力（ユーザーが添付するもの）

| 入力 | 形式の例 | 必須 |
|---|---|---|
| 訪問メモ | テキスト、音声メモの文字起こし、手書きメモを文字にしたもの | 必須 |
| 確認済みの顧客情報 | 表、テキスト（店名、担当者の役職、前回の合意事項） | 任意（あれば前回との差分を出す） |
| 報告の書式 | 過去の報告書の見本、CRM の項目一覧 | 任意（あれば項目をそろえる） |

書店名・担当者名はメモに書かれているものをそのまま使い、補わない。

## 手順

1. **メモを訪問（店舗）単位に分ける**。訪問日、店名、面談した相手（メモの記載どおり）を残す。
2. **発言を4つに分ける**。
   - 要望：相手から出た依頼・意見（「フェアをやりたい」「POP がほしい」など）
   - 合意事項：双方で決まったこと（数量・期日・条件が明記されているもの）
   - 宿題：こちらが持ち帰ったこと（見積、資料送付、確認）
   - 次回確認事項：相手が検討中のこと、返事待ちのこと
3. **「興味あり」と「受注」を分ける**。数量・期日・条件がそろっていないものは合意事項に入れず、次回確認事項にする。
4. **数量・期日・金額を取り出し、メモの記載どおりに書く**。曖昧な表現（「けっこう」「来月あたり」）はそのまま残し、「要確認」を付ける。
5. **前回の合意事項が添付されていれば、差分を出す**（進んだ／変わった／触れられなかった）。
6. **出力の最後に、人が確認する3点を再掲する**。

## 出力形式

### 1. 訪問報告（店舗ごと）

| 項目 | 内容 |
|---|---|
| 訪問日 | |
| 店名・売場 | |
| 面談した相手（メモの記載どおり） | |
| 要望 | 箇条書き |
| 合意事項 | 箇条書き（数量・期日・条件を含むものだけ） |
| 宿題（こちらの対応） | 箇条書き。期限があればメモの記載どおり |
| 次回確認事項 | 箇条書き。「興味あり」「検討中」はここ |
| 要確認（曖昧な数量・期日・表現） | 箇条書き |

### 2. 宿題の一覧（複数店舗を横断）

| 店名 | 宿題 | 期限（メモの記載どおり） | 状態（未着手） |
|---|---|---|---|

### 3. 人が確認すること（出力の末尾に必ず入れる）

- 合意事項が本当に決まったことか（受注と検討を混同していないか）
- 数量・期日・金額がメモどおりか（聞き間違い・書き間違いの可能性）
- 記録に残してよい内容か（相手の私的な発言、他社の情報）

## やらないこと

- メモにない要望・合意・数量を補わない。
- 「興味あり」「前向き」を受注・合意にしない。
- 相手の発言を評価しない（「脈あり」「見込み薄」など）。
- CRM・営業管理表に登録しない。書店や上司へ送信しない。外部サービスに接続しない。
- パスワードやトークンをユーザーに求めない。

## よくある失敗

- 「◯冊くらい置けそう」を合意事項の数量にする → 次回確認事項にし、数量は「要確認」。
- 複数店舗のメモが1つの文章になっていて、店舗の切れ目を誤る → 切れ目が不明な箇所は「店舗の区切り要確認」と書く。
- 宿題の期限を「なるべく早く」→「今週中」に置き換える → メモの表現のまま残す。
- 前回の合意事項を今回の報告に混ぜる → 差分の欄に分けて書く。
